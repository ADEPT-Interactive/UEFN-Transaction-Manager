# Generated Verse Public API Contract

Status: Phase 11 corrected interaction bindings, following the Phase 10 editable organization and Phase 9 canonical pre-release API cleanup, 2026-08-18

This document defines the one supported Verse surface generated by UEFN Entitlement Manager. The managed Verse file is regenerated from project data and must not be edited manually. Creator-authored gameplay, save logic, and reward effects belong in the creator's own Verse.

## One canonical API

Generated public symbols derive from each persisted `verseKey`, not from its editable display name. UEM does not generate a selectable API mode or preserve historical public aliases. Opening a supported old UEM project loads its catalog and regenerates this same canonical output.

The managed-data schema is independent of generated symbol names. `schemaVersion` remains the persisted manifest marker; supported schema versions 2, 3, and 4 continue to load. Obsolete generated-API metadata and old persisted purchase-event fields are tolerated while reading and omitted from newly generated manifests.

## Representative inventory

The representative fixture in `tests/public-api-fixture.ts` contains four entitlements, one alternate offer, three bundles including a dynamic bundle, two focused storefronts, restrictions, bindings, and auto-consume. It generates 96 explicit `<public>` declarations and 7 UEFN-exposed `@editable` arrays. Those arrays use stable role names such as `AccessPass_PurchaseTriggers`, `AccessPass_PurchaseButtons`, `AllOffersStore_OpenButtons`, and `CoinStore_OpenTriggers`.

| Category | Fixture count | Supported surface |
| --- | ---: | --- |
| Icon, metadata, entitlement, price, and offer declarations | 59 | Generated modules and offer data required by UEFN |
| Entitlement events | 12 | Three tuple events per entitlement |
| Grant and consume helpers | 6 | `Grant<Stem>` and consumable `Consume<Stem>`, returning `logic` |
| Ownership query helpers | 8 | `Get<Stem>Count` and `Has<Stem>` per entitlement |
| Purchase helpers | 8 | `Open<Stem>Purchase` for entitlements, alternates, and bundles |
| Global storefront helper | 1 | `OpenAllOffersStore` |
| Focused storefront helpers | 2 | `Open<StoreStem>` |

Generated device classes remain placeable UEFN devices without a public class declaration. Editable trigger, button, and storefront arrays are editor configuration rather than a promise that external Verse should mutate them.

## Supported developer API

For an entitlement with stable key `durable_entitlement`, the generated device exposes:

```verse
Transactions.OpenDurableEntitlementPurchase(Player)
Transactions.DurableEntitlement_GrantedEvent.Subscribe(OnGranted)
Transactions.DurableEntitlement_RemovedEvent.Subscribe(OnRemoved)
Transactions.DurableEntitlement_ReconciledEvent.Subscribe(OnReconciled)
Transactions.GetDurableEntitlementCount(Player)
Transactions.HasDurableEntitlement(Player)
```

The generated events are authoritative entitlement-delta signals:

```verse
<Stem>_GrantedEvent<public>:event(tuple(player, int))
<Stem>_RemovedEvent<public>:event(tuple(player, int))
<Stem>_ReconciledEvent<public>:event(tuple(player, int))
```

One positive delta signals only `<Stem>_GrantedEvent`. One negative delta signals only `<Stem>_RemovedEvent`. Reconciliation signals only `<Stem>_ReconciledEvent`, with the current owned count, including zero. No redundant player-only event families are generated.

`Grant<Stem>` and consumable `Consume<Stem>` are suspending public helpers returning the native Marketplace operation result as `logic`. Non-positive quantities return `false` without calling Marketplace. A `true` result reports the Marketplace operation boundary, not completed gameplay processing, so gameplay should continue to subscribe to the canonical events.

`Get<Stem>Count` queries current Marketplace state for the concrete entitlement and returns zero when no matching result exists. `Has<Stem>` returns whether that current count is greater than zero. Alternate offers share the parent entitlement queries; bundles and storefronts do not get ownership queries.

`Open<Stem>Purchase` is the guarded purchase entry point for each entitlement, alternate offer, and bundle. Internal `ExecuteBuy…` functions perform the suspending Marketplace call. `OpenAllOffersStore` and `Open<StoreStem>` are guarded storefront entry points. Lower-level `Show…` functions used by those entry points remain internal and are not public compatibility APIs.

Paid-random classification remains on entitlement metadata. Odds are optional inside UEM and are included in generated descriptions only when supplied; accurate odds must still be disclosed to players before purchase through UEM or another clear island disclosure.

## Project-data compatibility

Project-data compatibility is intentionally separate from generated public API compatibility. UEM preserves valid persisted `verseKey` values, `retiredVerseKeys`, entitlement and bundle references, storefront configuration, and supported schema loading. Missing, malformed, reserved, and duplicate keys are repaired deterministically and surfaced as project-data diagnostics. A valid key such as `starter_bundle2213124124` remains unchanged.

Old manifests may contain fields from temporary pre-release API experiments, including generated API markers, compatibility flags, diagnostics, and purchase-event names. UEM ignores those obsolete fields, preserves the actual catalog data, and regenerates the current canonical API. Newly created and cleaned manifests do not write them.

UEM still refuses to import an unmanaged Verse file because guessing its structure could lose data. A managed file is always regenerated from its embedded project manifest.

## Deliberate boundaries

This phase corrects generated interaction binding semantics. It does not change stable identity rules, project schema support, paid-random disclosure guidance, restriction behavior, `GetMinPurchaseAge`, query helpers, Grant/Consume result behavior, auto-consume, or authoritative entitlement event processing.

UEFN editables use the current native `@editable:` metadata block with localized `ToolTip` and `Categories` messages. Categories are emitted as a flat native category path: root (`ENTITLEMENTS` or `STOREFRONTS`), stable object display label, then role (`Purchase Triggers`, `Purchase Buttons`, `Open Triggers`, or `Open Buttons`). Display names affect category text and tooltip text only.

Purchase triggers are supported deliberate-interaction entry points. UEM passes the triggering player to `Open<Stem>Purchase`, while creators remain responsible for wiring a trigger behind a deliberate player interaction. Purchase buttons are the straightforward recommended binding: an interaction passes the button's player to the same canonical helper. Both callbacks remain thin and use the existing in-flight-safe public entry points.

Passive Mutator Zone purchase bindings and the old automatic-zone-prompt setting are no longer generated. Old manifests and imported project settings containing those fields load safely, ignore the obsolete values, and show a non-blocking migration warning. Existing custom editable-name fields are also tolerated and ignored. The global storefront intentionally remains a button binding while focused storefronts retain their existing trigger binding; broader storefront binding symmetry is deferred until storefront membership and authoring UX are revisited.

The repository does not claim live UEFN editable-assignment persistence verification when the editor or Verse Workflow Server is unavailable. Before release, test whether existing placed-device assignments survive the Phase 10 editable renames in a real open UEFN project.

The following work remains deferred: shared purchase or storefront executors, unified Marketplace UI locking, reconciliation optimization, dynamic-offer parity, MaxCount deduplication, storefront membership UI, broader storefront binding symmetry, broad Marketplace validation changes, logging overhaul, namespace facades, unrelated Manager quality-of-life fixes, and launcher all-drive discovery.
