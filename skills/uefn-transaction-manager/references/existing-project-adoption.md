# Existing-project transaction adoption

This is a semantic migration, not a text-only rename.

1. Start a read-only `begin_activity`, discover both servers and their live schemas, compare canonical project identity, and read the UTM snapshot/revision.
2. Call UTM `preflight_operation` for `full-existing-project-migration` with the agent-reported Unreal evidence. If Unreal MCP is missing, mismatched, uninspected, or incomplete, stop with zero mutation. Never turn this operation into catalog-only; request the separate explicitly approved `catalog-only-migration` only when the owner chooses a labeled partial result.
3. Use Epic MCP to search all relevant project Verse. Trace Marketplace declarations, purchase calls, alternate paths, bundles, storefront arrays, ownership/count checks, grants, consumes, dynamic values, restrictions, comments, strings, device references, and associated Texture2D assets.
4. Classify every candidate as confirmed, inferred, ambiguous, or absent. Exhaustive evidence that a concept does not exist is absent, not ambiguous.
5. Build a non-destructive mapping of transaction intent and a required parity table with one row for every migrated entitlement, alternate offer, and bundle. Every row must compare legacy and proposed identity, Name, Description, ShortDescription, item type, MaxCount, immediate-use evidence, `autoConsume`, price, restrictions, icon source, gameplay consequence/event boundary, repeated-purchase behavior, and relationships. Preserve unmatched existing UTM records by default; delete only when the evidence proves replacement or the creator explicitly authorizes it. Stop only if an ambiguity could change what is sold, owned, granted, consumed, priced, restricted, or eligible.
6. Call UTM `validate_migration_parity` with the table. Then use `apply_catalog_patch` dry-run with `migration.mode: "existing-project"`, the same parity table, explicit stable operation IDs, and the current revision. UTM rejects the patch before mutation if the table is missing, incomplete, inferred, ambiguous, absent, or contradictory. Inspect operation results/cascades/validation, then begin a mutating activity and apply atomically with the still-current revision, token, and activity ID.
7. Heartbeat and update the user-safe phase between catalog, icon, save, external Verse, and compile work. If the revision, project, editor state, or capability evidence changes, end the activity and run preflight again; never revive an expired token or heartbeat.
8. Adopt associated icons through Epic Texture2D discovery followed by UTM `adopt_icon`. Save with UTM and request the current integration contract.
9. Rewrite only the external project Verse callers and gameplay integration through Epic MCP. Preserve calculations, eligibility, UI, and gameplay consequences outside the managed file. An immediate-use legacy purchase maps to consumable `autoConsume`; apply its gameplay consequence from the generated `Await<Stem>ConsumedEvent()` after the generated helper's intent is matched to an authoritative negative entitlement delta, never from `Granted` and never by treating generic `Removed` as proof of explicit consumption. Inventory-bearing consumables remain non-auto-consumed.
10. Compile through Epic MCP, rescan the full project for leftover raw Marketplace plumbing and duplicate purchase paths, configure proven device fields, reconnect after project switching when necessary, and perform a final semantic audit.
