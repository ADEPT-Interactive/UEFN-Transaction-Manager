# Greenfield transaction workflow

1. Use `catalog-edit` for creating/saving the catalog: start read-only activity, inspect UTM context/snapshot, and preflight. End discovery, then begin the matching mutating activity with its token. Epic MCP is not required for this catalog-only step.
2. If the managed Verse file is absent, stop until the exact project is open in UEFN, the authenticated editor bridge is fresh, and Python Editor Scripting is enabled. The first mutation must provision UTM's native placeholder and confirm its exact object path before the catalog can be persisted.
3. Create entitlements, alternate offers, bundles, and storefront membership through UTM MCP. Let UTM allocate IDs and stable Verse keys.
4. Use the verified placeholder for catalog setup. If custom icons were requested, discover exact Texture2D objects through Epic MCP and run a separate `native-icon-adoption` preflight/activity; never invent paths or copy `.uasset` files.
5. Call `validate_catalog`, resolve errors, and use `save_catalog` with the current revision. Save is blocked if any primary, alternate, or bundle icon cannot be resolved to a confirmed project asset.
6. Call `describe_integration_contract`. If the request includes gameplay integration, discover matching Epic project context and preflight `verse-integration` before writing external caller/device Verse using the returned symbols.
7. When external integration/compilation was requested, use Epic MCP under its matching operation. Place/configure a managed device only with the supported device operation preflight; do not require placement or compilation merely to save a catalog.
8. Run session verification only if requested and available; otherwise report the strongest completed structural/compile evidence. For any durable whose ownership affects live-session behavior, initialize external state from the generated reconciliation/authoritative ownership path and keep a persistent `Await<Stem>GrantedEvent()` path for same-session acquisition; use `Await<Stem>RemovedEvent()` only when the current contract and project semantics require it. Do not perform a real purchase. Audit that the managed file remains manager-owned and gameplay logic remains external.
